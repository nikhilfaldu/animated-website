# docs/stories/STORY-hero-assembly.md

## Title

Hero: Assembly — Formation Through Gravity

## Goal

Turn the first user input (scroll or keyboard) into ignition: the emblem assembles and the headline crystallizes from that motion, establishing the “living orbital system” and the site’s motion language.

## Narrative Link

Act 1: Assembly — radials arrive and form the emblem; typography emerges from negative space during formation.

## User Story

As a visitor, on my first scroll I want to experience the system “finding itself,” so I immediately understand the organizing principle and feel confident in the craft.

---

## Core Interaction (Authoritative Outline)

**Initial:** near-still particulate drift; emblem latent (reduced opacity).
**Trigger:** first scroll delta (mouse/trackpad/keyboard) or first touchmove.
**Ingress:** radials arc inward (gravitational curves), snapping into a stable emblem.
**Reveal:** headline is revealed *through* the assembly (mask/clip-path), then locks readable.
**Lock:** emblem rests; subtle micro-bass “lock” (Tone.js), ready for Orbit.

### Assembly State Contract (OrbitSystem)

Add/confirm in `OrbitSystem`:

* State: `'assembly'` with motion values `{ scale, rotateZ, opacity, originX, originY }` and per-radial offsets.
* Methods:

  * `animateTo('assembly', duration)`
  * `setCustomTransform({...})`
  * `staggerRadials(order: number[], opts: { delay: number; curve: 'gravity'|'linear' })`
    These match the described API patterns in `CLAUDE.md` and PRD (state and transforms).

**Example (usage shape):**

```ts
// Hero.tsx (pseudo-usage)
const { animateTo, setCustomTransform, currentState, staggerRadials } = useOrbitSystem();

useEffect(() => {
  if (firstScrollStarted) {
    // Left-pin expansion handoff during ingress (preserve from V1)
    setCustomTransform({ originX: 50, originY: 50, scale: 4, opacity: 0.75 }); // pre-ingress posture
    animateTo('assembly', 1.2); // drive global posture timing
    staggerRadials(radialOrder, { delay: 0.012, curve: 'gravity' }); // per-radial
  }
}, [firstScrollStarted]);
```

This aligns with the state and transform samples described in the docs.

## Headline Reveal Pattern (Mask-first, Always-Readable)

### Approach

Use an **SVG mask/clip-path** that keys off emblem radial assembly progress. The headline is present from frame 0 (for accessibility and SEO), but its *reveal* is synchronized to emblem ingress.

**Structure (Hero.tsx)**:

```tsx
<section id="hero" className="min-h-[120svh] grid place-items-center">
  <div className="relative w-full max-w-[1100px] px-6">
    {/* Emblem is fixed globally in App; here we only orchestrate assembly */}
    <h1 className="font-display h0 leading-tight text-fg">
      <span className="sr-only">Creative websites for brands beyond the template</span>
      {/* Visible line with mask */}
      <span
        aria-hidden
        className="block will-change-transform"
        style={{
          WebkitMaskImage: `url(#emblem-mask)` /* fallback handled below */,
          maskImage: `url(#emblem-mask)`
        }}
      >
        Creative websites for brands beyond the template
      </span>
    </h1>

    {/* SVG mask layer (overlay, pointer-events:none) */}
    {/* Use emblem assembly values to animate the mask paths */}
    {/* Reduced-motion: skip dynamic path; use simple fade-in of headline */}
  </div>
</section>
```

**Mask Generation**

* Option A: render an offscreen SVG that mirrors the 32 emblem radials (from `EMBLEM_PATHS`) and animate their stroke/fill to “paint” the mask in as assembly completes.
* Option B: simpler circular mask that scales with `assemblyProgress`, then refine to radial paths in Phase 2.

**Best practice:** headline remains readable; mask never reduces contrast below AA for more than ~300ms (acceptance criterion below).

## Motion Language (curves & timing)

* **Ingress curve:** `cubic-bezier(0.25, 0.46, 0.45, 0.94)` for confident arrival
* **Overshoot damp:** short spring tail, ζ ≈ 0.65 (Framer spring), clamped amplitude.
* **Stagger:** 8–12ms per radial (32 total), grouped into quadrants to avoid visible “wipe.”

**Example (Framer Motion pseudo):**

```ts
const radialVariants = {
  hidden: ({ i }) => ({ opacity: 0, rotate: 45, pathLength: 0 }),
  show: ({ i }) => ({
    opacity: 1,
    rotate: 0,
    pathLength: 1,
    transition: {
      opacity: { duration: 0.25, ease: 'easeOut', delay: 0.012 * i },
      rotate:  { duration: 0.6, ease: [0.25,0.46,0.45,0.94], delay: 0.012 * i },
      pathLength: { duration: 0.7, ease: 'easeOut', delay: 0.012 * i }
    }
  })
};
```

## First-Scroll Detection & Safety

Use Lenis + a one-shot state in `ScrollController` to detect the **first non-zero** delta (wheel, touchmove, keyboard). On detection:

* fire `dispatch({ type: 'FIRST_SCROLL' })` to OrbitSystem/hero orchestrator.
* ensure keyboard (Space/PageDown/Arrow) and anchor-link scroll also trigger it (Lenis handles anchors).

**Guardrails:**

* Debounce by one animation frame to avoid multiple triggers.
* If user lands mid-page (history, anchor), auto-trigger assembly once.

---

## Accessibility (WCAG + Reduced Motion)

* Headline text is present and selectable at T0; masking never hides it for >300ms.
* Respect `prefers-reduced-motion`:

  * Skip radial stagger and mask travel; fade+scale the headline to `opacity:1` and `scale:1.0` over ~240ms.
  * Emblem jumps to “assembled” static pose (no curve travel).
* Ensure minimum color contrast of headline vs `--bg` according to palette.

**Reduced Motion Example:**

```ts
const prefersReduced = useReducedMotion(); // existing hook in codebase:contentReference[oaicite:17]{index=17}
const headlineAnim = prefersReduced
  ? { opacity: 1, y: 0, transition: { duration: 0.24 } }
  : { opacity: [0.001, 1], y: [10, 0], transition: { duration: 0.6, ease: 'easeOut' } };
```

## Performance Budget

* GPU transforms only (`transform`, `opacity`).
* Cap particles ≤ 200 global (shared budget).
* Avoid layout thrash: compute assembly progress from `useScroll` / motion values; no DOM measurements in tight loops.
* Limit concurrent Promises; prefer rAF-driven state.
* Avoid heavy R3F in Hero; reserve WebGL for later acts (Positioning, Data) per roadmap.

---

## Audio Micro-Feedback (Tone.js, optional, gated)

* Single short sine/sub bass “lock” at assembly completion; amplitude tied to `prefers-reduced-motion` (or a future `prefers-reduced-audio`).
* Mute by default on mobile; enable post-gesture only (autoplay policies).

## Acceptance Criteria

1. **Readability:** Headline remains readable; masking does not reduce legibility >300ms.
2. **Determinism:** First scroll *always* triggers assembly (wheel/touch/keyboard/anchor).
3. **Performance:** 60 FPS target on modern laptops; no more than one minor hitch (<32ms) during ingress.
4. **Parity:** Left-pin origin handoff preserved exactly as defined in PRD/V1 notes.
5. **A11y:** Reduced-motion path renders without travel/stagger; keyboard navigation unaffected.
6. **Cleanup:** All listeners and rAF loops are cleaned on unmount.

---

## Dependencies & Integration

* **OrbitSystem**: states & motion values + `animateTo`, `setCustomTransform`, `staggerRadials`.
* **EMBLEM_PATHS** for mask geometry (optional Phase 2).
* **Lenis** for smooth/consistent first-scroll capture.
* **Theme Flip/Portal**: no theme flip occurs in Hero; ensure compatibility with global system when transitioning to Orbit later.
* **App Layout**: Emblem is fixed and centered in `App.tsx` (`fixed top-1/2 left-1/2`), which is acceptable for MVP Assembly; later sections will reposition per narrative.

---

## Phased Delivery (to de-risk)

* **Phase 1 (MVP):** First-scroll detection → emblem assembly pose → headline fade/scale (no mask).
* **Phase 2:** SVG mask bound to assembly progress using emblem radials; quadrant-grouped stagger.
* **Phase 3:** Add subtle particle ingress + Tone.js lock; polish curves and overshoot damp.
